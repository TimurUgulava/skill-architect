# Шаг 5. Проверить

Скилл без проверки — гипотеза. Проверка обязательна, а её отчёт называет,
что именно делалось: прогон, сравнение или чтение по тексту. Отсутствие
проверки — законный факт, который сообщают; выдать непроверенное за
проверенное — нет.

## Что проверять

| Проверка | Как понять, что прошла |
|---|---|
| Триггер «должен» | Три-пять запросов в разных формулировках, включая неявные, без названия скилла — скилл выбран |
| Триггер «не должен» | Три-пять near-miss: соседние скиллы, смежные домены, те же слова с другой задачей — скилл не выбран |
| Типовая задача | Результат соответствует тому, что на шаге 2 названо правильным |
| Редкий маршрут | Режим, который встречается в одном запуске из пяти, находит свой референс по условию чтения |
| Защитная зона | Внешнее действие останавливается на подтверждении; секреты не читаются; нормативная формулировка на месте |
| Определение готовности | Задача, где первый вариант рабочий, но неполный: скилл доводит до списка «готово», а не приходит за одобрением раньше |
| Разрешения | Задача, где по пути нужно обратимое действие из полки разрешённого: скилл делает его сам, не спрашивая |
| Без скилла | Та же задача в чистом контексте без скилла — видно, что именно скилл добавил; если ничего, скилл не нужен |

## Уровни по убыванию силы

Делай самый сильный из доступных, называй в отчёте, какой.

**1. `claude plugin eval`** — когда скилл лежит в плагине (есть
`.claude-plugin/plugin.json` или каталог `skills/`) и Claude Code не старше
2.1.269. Каждый кейс прогоняется трижды с плагином и трижды без, грейдеры
`regex`, `tool_used`, `tool_order`, `file_exists` бесплатны, `llm` и
`baseline` зовут судью. Дельта «с/без» и есть вклад скилла. Суита создаётся
диалогом `claude plugin eval init`; для CI — `--trust-plugin --json
--threshold --no-publish --max-cost-usd`. Платно: каждый прогон — вызовы
модели.

**2. `skill-creator`** — официальный плагин
(`/plugin install skill-creator@claude-plugins-official`). Хранит кейсы
в `evals/evals.json` внутри скилла, гоняет субагентами с чистым контекстом
со скиллом и без, слепо сравнивает две версии, подбирает description по
триггерным запросам. Формат кейса: `prompt`, `expected_output`,
`expectations` (проверяемые утверждения), `files`.

**3. Прогон субагентами вручную** — когда плагинов нет. На каждую проверку
из таблицы — отдельный субагент с чистым контекстом: он получает текст
скилла и запрос, не получает этой сессии и твоих рассуждений. Судья —
ещё один субагент с рубрикой (`rubric.md`), которому не сказано, какая
версия перед ним. Сохраняй выходы на диск: сравнивать по памяти нельзя.

**4. Статическая сверка** — всегда, но это не проверка поведения. Механику
отдай скрипту, он видит то, что глаз пропускает:

```
python3 ${CLAUDE_SKILL_DIR}/scripts/check_skill.py <путь к скиллу>
```

Маршруты, осиротевшие справочники, одна норма в двух файлах, обязательные
разделы, капс без причины, личные пути, похожее на секреты. Ноль находок
означает только, что механика в порядке; так и называй: «проверено чтением
и скриптом».

`/skill-doctor` показывает, сколько контекста стоит каждый установленный
скилл и как часто он вызывался за неделю. Это про цену и востребованность,
не про качество; полезен после установки, чтобы увидеть, что description
не слишком длинный и скилл вообще срабатывает.

## Слепое сравнение версий

Для существенных правок: обе версии на одних задачах, выходы отдаются
судье под метками A и B без указания, где старая. Судья оценивает по рубрике
и называет победителя; только потом раскрывается, кто есть кто, и
разбирается, почему. Автор, знающий, где его правка, будет её защищать.

## Когда проверка провалилась

Читай транскрипт, не только результат: где модель обошла инструкцию, чего
не нашла, что сделала лишнего. Исправляй обобщённо: не патч под один кейс
и не новое «никогда», а формулировка цели, которая покрывает и этот случай.
Если все прогоны независимо пишут один и тот же вспомогательный код —
это скрипт в `scripts/`. Если инструкция заставляет модель делать
непродуктивные шаги — убери её и посмотри, что изменится.

## Отчёт о проверке

Три списка: что прогнано и с каким исходом; что проверено только чтением;
что не проверялось вовсе и почему. Числа — только пересчитанные. Без
третьего списка отчёт неполный.
