# Архитектурные паттерны

Паттерн — форма хода работы. Степень свободы выбирается отдельно
(`design.md`) и не вытекает из паттерна: последовательный процесс может
быть высокосвободным, если каждый шаг — цель, а не метод.

## 1. Последовательный процесс

Шаги зависят друг от друга, у каждого понятный выход. Форма: нумерованный
список, где у шага названа цель и что считается его завершением. Точки
остановки — только там, где следующий шаг дорог или необратим.

## 2. Итеративное улучшение

Результат улучшается за циклы «сделать → оценить по рубрике → исправить».
Нужна рубрика с проверяемыми критериями и порог остановки; без них цикл
бесконечен или останавливается по настроению. Оценку часто лучше отдавать
судье в чистом контексте.

## 3. Выбор по контексту

Одна цель, разные подходы по сигналу: тип файла, источник, режим. Форма:
таблица «сигнал → маршрут», а не цепочка «если… то…». Каждая ветвь —
отдельный референс со своим условием чтения; взаимоисключающие ветви
законно противоречат друг другу.

## 4. Доменное знание

Скилл несёт знание, которого у модели нет: термины, нормы, вкус автора.
Форма: короткая карта в теле, богатые референсы в ветвях — образцы,
рубрики, схемы. Здесь пример остаётся носителем требования; здесь же
чаще всего живут правила из зоны «закон и приватность» — дословно.

## 5. Координация внешних сервисов

Ход работы через несколько MCP или API. Форма: назначение каждого сервиса
одной строкой, порядок вызовов, поведение при отказе (повтор, откат,
остановка). Инструкции по использованию инструмента — в его описании, не в
скилле. Внешние действия с побочным эффектом — через подтверждение.

## Антипаттерны

| Антипаттерн | Почему плохо | Что вместо |
|---|---|---|
| Шаги процесса в description | Модель следует description и не читает тело | Description — назначение и триггеры |
| «Всегда/никогда» вне трёх зон | Правило ошибается на части запросов, модель тратит рассуждение на разруливание | Цель и границы |
| Императив без причины в защитной зоне | Правило снимут при следующей чистке как лишнее | Причина рядом с правилом |
| Единственный пример как носитель формата | Все результаты — его вариации | Несколько образцов и правило выбора, либо схема |
| Референс без условия чтения | Никогда не откроется или откроется не тогда | «Открой, когда…» в корне |
| Одна норма в двух файлах | Копии расходятся, правка не доезжает | Один адрес, остальные ссылаются |
| Факты о пользователе в теле | Скилл не переносится, память дублируется | Память Claude, образцы |
| Внешнее действие без подтверждения | Необратимо; откат не отменяет отправленное | Показать и ждать «да»; `disable-model-invocation` |
| Пачка примеров вызова инструмента | Зажимает пространство поиска | Выразительный интерфейс: аргументы, перечисления, схема |
| Тело как свод всего, что автор знает | Каждая строка — плата в каждом ходу | Маршрутизатор и ветви |
