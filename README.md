# Skill Architect

Скилл для [Claude Code](https://code.claude.com/docs), который проектирует,
собирает, проверяет и ревизует другие скиллы. Версия 2.0 пересобрана под
практики контекст-инжиниринга поколения Claude 5: Anthropic удалили больше 80%
системного промпта Claude Code без потерь на своих оценках и описали, что
изменилось в том, как писать инструкции для этих моделей
([статья](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models),
24 июля 2026). Скилл применяет эти выводы к тому, что он порождает, и к себе.

## Что делает

Берёт запрос («сделай скилл, который…»), материалы и проект, и проводит через
пять шагов: разобраться → спроектировать → собрать → проверить → разместить.
На выходе — директория скилла: `SKILL.md` как маршрутизатор, `references/` с
условиями чтения у каждой ветви, `scripts/` для хрупкого и детерминированного,
`evals/` с контрольными задачами, и отчёт автору: что проверено, чем, что нет.

Три режима:

| Режим | Когда | Что происходит |
|---|---|---|
| **Создать** | «сделай скилл», описание задачи, материалы | Пять шагов с двумя точками остановки: после разбора, если есть развилки, и после архитектуры |
| **Проверить** | «проверь скилл», «не триггерится», «странно себя ведёт» | Триггеры «должен / не должен», типовая задача, редкий маршрут, защитная зона, прогон без скилла; уровни от `claude plugin eval` до статической сверки |
| **Ревизия** | «обнови под Claude 5», «раздулся», «почисти» | Сигналы по шести сдвигам, наборы правок `CHG-N` с откатом, контрольная корзина, отчёт «простыми словами». По умолчанию — только отчёт |

## Зачем это, если можно просто попросить модель «сделай скилл»

Можно. И получится файл с алгоритмом из десяти атомарных шагов, десятком
«ВСЕГДА» и «НИКОГДА», примерами вызова инструментов и description, куда
уехал весь процесс. Работать будет — пока не окажется, что скилл переспрашивает
известное, срабатывает на чужие запросы, отправляет письмо без подтверждения
или тратит две тысячи токенов в каждом ходу на то, что модель и так умеет.

Ценность здесь не в промпте, а в том, что скилл держит дисциплину вокруг шести
сдвигов из статьи и не даёт собрать скилл под модель, которой уже нет.

| Проблема | Что делает Skill Architect |
|---|---|
| Скилл нужен не всегда, но собирается всегда | **Шаг 0**: справится ли модель без скилла? Если да — скилл не нужен, предлагается меньшее |
| Обязательный опрос из пяти вопросов на любой запрос | **Вопросы только по развилкам** — там, где разные ответы дают разные скиллы. Чёткий запрос идёт в работу с допущениями вслух; размытый не проектируется вслепую |
| «Атомарные шаги, свобода низкая» для задач, где важен результат | **Цель и границы вместо метода.** Степень свободы — отдельный выбор: скрипт для хрупкого, суждение для вкуса |
| «ВСЕГДА / НИКОГДА» на каждом шагу | Императив только в **трёх зонах**: необратимые внешние действия, закон и приватность, известная боль проекта — и с причиной |
| Скилл отправляет, публикует, платит без подтверждения | **Защитные зоны** обязательны: показать, что уйдёт, и ждать «да»; `disable-model-invocation` для опасного |
| «Пиши живо, тон дружелюбный» вместо голоса автора | **Богатые референсы**: маршрут к утверждённым образцам автора, рубрика, схема, тест. Образцы вкуса не сочиняются |
| Три примера вызова инструмента | **Интерфейс вместо примеров**: скрипт с говорящими аргументами, перечисление статусов, схема входа-выхода |
| Референс лежит, но когда его читать — неясно | **Условие чтения** у каждой ветви, выводимое до открытия файла |
| «Готово, упаковано» без проверки | **Проверка обязательна** и в чистом контексте; отчёт делит «прогнано / проверено чтением / не проверялось» |

## Как устроено

| Шаг | Что происходит | Справочник |
|---|---|---|
| **0. Нужен ли скилл** | Что модель сделает не так без него? Не названо — не нужен | `discovery.md` |
| **1. Разобраться** | Извлечь известное из запроса и проекта; спросить по развилкам; три вида запросов | `discovery.md` |
| **2. Спроектировать** | Что считается правильным результатом, чем измеряется, кто судья; паттерн и степень свободы; дерево файлов с условиями чтения; защитные зоны; frontmatter как архитектурные решения; схема на утверждение | `design.md`, `patterns.md` |
| **3. Собрать** | Актуальные поля frontmatter; description без шагов процесса; тело как путеводитель; references, scripts, assets; чек перед выдачей | `writing.md` |
| **4. Проверить** | Уровни по убыванию силы: `claude plugin eval` → `skill-creator` → субагенты в чистом контексте → статическая сверка; слепое сравнение версий | `verification.md`, `rubric.md` |
| **5. Разместить** | Проектная, личная директория или плагин; отчёт автору | `SKILL.md` |

## Установка

Проектно — в репозиторий команды:

```bash
git clone https://github.com/TimurUgulava/skill-architect .claude/skills/skill-architect
```

Лично — для всех своих проектов:

```bash
git clone https://github.com/TimurUgulava/skill-architect ~/.claude/skills/skill-architect
```

Скилл срабатывает сам на «создай скилл», «спроектируй скилл», «проверь скилл»,
«ревизия скилла», «обнови скилл под Claude 5» и по команде `/skill-architect`.

## Как проверялось

Версия 2.0 проверялась против версии 1.0 слепым сравнением, 14 сентября 2026.
Пять задач из `evals/evals.json` прогнаны обеими версиями в чистых контекстах
(отдельный субагент на задачу, пользователь недоступен, допущения фиксируются).
Выходы разложены по случайным меткам A/B, и пять независимых судей оценили их по
`references/rubric.md` с цитатами, не зная, где какая версия.

| Задача | v1.0 | v2.0 | Что решило |
|---|---|---|---|
| Типовой технический скилл (конспект YouTube) | 12/18 | 17/18 | v1.0 развернула опрос на чёткий запрос и задала метод восемью шагами; v2.0 сформулировала результат и границы, хрупкое вынесла в скрипт, приложила evals |
| Домен вкуса (посты в голосе автора) | 12/18 | 17/18 | v1.0 заменила посты автора производными правилами и сочинила примеры от его имени; v2.0 сделала маршрут к дословным образцам и рубрику |
| Внешнее необратимое действие (отчёт клиенту по почте) | 12/18 | 17/18 | v1.0 спроектировала режим отправки без человека (`--auto`); v2.0 — одно «никогда» с причиной, инструмент отправки не в `allowed-tools`, обходного режима нет |
| Ревизия существующего скилла | 14/18 | 17/18 | v2.0 дала пронумерованные правки с «было → стало», набор триггеров «должен / не должен» и ничего не применила без разрешения; v1.0 глубже разобрала слой данных, но повторила в исправленной версии дубли, которые сама нашла |
| Размытое ТЗ («скилл для работы с клиентами») | 4/8 | 8/8 | v1.0 задала анкету из пяти пунктов; v2.0 сама собрала контекст проекта, свела запрос к одной развилке из четырёх разных скиллов и отдельно спросила про отправку |

Что судьи нашли у v2.0: в трёх задачах из пяти порождённые скиллы всё же
повторяли порог или факт в `SKILL.md` и в ветви, хотя правило «один адрес» в
архитекторе было. После сравнения в `writing.md` добавлена механическая проверка
дублей поиском, а в `revision.md` — сигнал «детерминированное описано словами»;
эти правки после судей повторно не прогонялись. Полные вердикты и выходы прогонов
в репозиторий не включены.

Что это не доказывает: что скиллы, собранные v2.0, хороши в бою. Задачи
синтетические, судьи и исполнители — модели, порождённые скиллы на настоящих
данных не запускались.

## Границы

- Скилл проектирует скиллы, а не выполняет их задачи и не совершает внешних
  действий от их имени. Скилл с отправкой, публикацией или платежом он проверяет
  только чтением: отправленное необратимо.
- Режим ревизии для одного скилла. Пакет скиллов или весь проект — конфликты между
  скиллами, пересечение триггеров, зеркала и sync-скрипты — по полной
  [спецификации ревизии](https://github.com/TimurUgulava/claude-skills/tree/main/skill-revision-spec).
- Поля frontmatter и способы проверки взяты из документации Claude Code на
  сентябрь 2026; при выходе новых версий их стоит сверить.
- Контрольные задачи в `evals/` синтетические: они показывают, следует ли архитектор
  своим правилам, а не то, что порождённые скиллы хороши в бою.
