## [2.0.1] — 2026-09-14

### Изменено

- README рассказывает про скилл на одной живой задаче: запрос «скилл для отчётов
  клиентам по почте», отданный обеим версиям архитектора, что каждая из них
  спроектировала и как это оценил судья, не знавший, где какая версия.
- Ход работы показан схемой: шаг 0 с исходом «скилл не нужен», две точки
  остановки, где скилл ждёт автора, и петля ревизии, возвращающая готовый скилл
  в работу спустя месяцы.

### Исправлено

- В README не осталось ссылок, которые никуда не ведут.
- Учебная фикстура плохого скилла обезличена: она читается как пример, а не как
  чей-то настоящий файл.

## [2.0.0] — 2026-09-14

Пересборка под практики контекст-инжиниринга поколения Claude 5
([статья Anthropic](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models),
24.07.2026) и под [спецификацию ревизии скиллов](https://github.com/TimurUgulava/claude-skills/tree/main/skill-revision-spec) v2.0.
Скилл переписан целиком; имя и триггеры активации сохранены, набор триггеров расширен.

### Добавлено

- Режимы «Проверить» и «Ревизия» рядом с «Создать». Ревизия существующего скилла —
  сжатая версия спецификации для одного скилла: сигналы по шести сдвигам, «чего не
  делать никогда», наборы `CHG-N` с откатом, контрольная корзина, отчёт «простыми
  словами». Раньше редактирование существующих скиллов было в исключениях description
  и при этом существовало как «Фаза 4: Debug» — конфликт снят.
- Шаг 0 «нужен ли скилл»: проверка, справится ли модель без него; исход «не нужен» —
  нормальный.
- Разбор по развилкам вместо обязательного опроса из пяти вопросов; три вида запросов
  (чёткий, с развилками, размытый) и поведение для каждого.
- Защитные зоны — единственное место обязательной жёсткости: необратимые внешние
  действия с подтверждением человека в императивной форме, секреты, закон и приватность,
  известная боль проекта. Архитектор больше не может собрать скилл, который отправляет
  без подтверждения.
- Богатые референсы: маршрут к утверждённым образцам автора вместо описания словами,
  рубрика как референс, схема и тест как спецификация; запрет сочинять образцы вкуса.
- Условие чтения у каждой ветви как требование к порождаемым скиллам.
- Актуальные поля frontmatter (`when_to_use`, `argument-hint`, `arguments`,
  `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`,
  `model`, `effort`, `context`/`agent`/`background`, `hooks`, `paths`, `shell`) как
  архитектурные решения; подстановки и динамический контекст.
- `references/verification.md`: уровни проверки по убыванию силы — `claude plugin eval`
  с baseline «без плагина», `skill-creator` с `evals/evals.json`, прогон субагентами в
  чистом контексте, статическая сверка; слепое сравнение версий; честный отчёт
  «прогнано / проверено чтением / не проверялось».
- `references/rubric.md`: девять осей оценки готового скилла, по которым скилл
  проверялся сам (см. README, «Как проверялось»).
- `evals/`: пять контрольных задач в формате `skill-creator` с ожиданиями и фикстурой
  плохого скилла для режима ревизии.
- Репозиторий: README, CHANGELOG, LICENSE (MIT).

### Изменено

- Принцип «атомарная детализация, степень свободы низкая по умолчанию» заменён на
  «цель и границы вместо метода; степень свободы — отдельный выбор». Причина:
  модель поколения Claude 5 выбирает метод сама, предписание нужно только там, где
  цена ошибки высока или нужна воспроизводимость.
- Норма «SKILL.md ≤ 100 строк», жившая в трёх файлах, заменена на официальный ориентир
  «короче 500 строк, маршрутизатор обычно втрое короче» в одном месте.
- «Делай description настойчивым — скиллы склонны к undertriggering» снято:
  перетриггеривание бьёт по соседям сильнее. Вместо напора — near-miss-исключения
  и проверка триггеров «должен / не должен».
- Обязательные «минимум два примера» у каждого порождаемого скилла сняты: пример
  остаётся носителем вкуса автора, механику несёт интерфейс (скрипт с аргументами,
  перечисление, схема).
- Чтение проекта архитектору разрешено: без него нельзя провести границу триггеров
  и найти эталоны. Запрет остался на выполнение целевой задачи и внешние действия.
- Пять паттернов сохранены; степень свободы отвязана от паттерна; таблица
  антипаттернов переписана под шесть сдвигов.
- Точки остановки: две обязательные (после разбора при развилках, после архитектуры)
  вместо вопросов на каждом шаге.

### Удалено

- Упаковка в `.skill` и зависимость от `package_skill.py` из плагина `skill-creator`:
  формата `.skill` в официальной документации нет, скиллы распространяются
  директориями (проектной, личной, в плагине).
- `references/eval-guide.md` с командами `python -m scripts.run_loop` без самих
  скриптов — заменён на `verification.md` с реально доступными способами.
- `examples/example-invoice-skill.md` — единственный пример якорил структуру всех
  порождаемых скиллов; вместо него рубрика и образцы по типам в `design.md`.
- Шаблон User Guide из debug-guide — отчёт автору описан в шаге 5.
